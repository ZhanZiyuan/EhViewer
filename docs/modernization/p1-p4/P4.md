# P4：CI 与供应链

## 修改文件与行为

- `.github/workflows/ci.yml`：push过滤改为 `**`，覆盖 feature/rusty；合并旧 default/marshmallow 为一个 Android build job。contents:read，checkout不保留credentials，PR不发布，Rust/Gradle缓存只由 main 非PR写入。
- 检查 fmt、3项离线parser test（跳过3项联网测试）、三ABI locked Clippy、build-logic/Spotless、现有unit task、Lint、Debug/Release/AndroidTest/benchmark编译。NO-SOURCE仍显式记录。
- 三APK splits与universal保留 ABI 产物名称，避免破坏内置CI更新器；仅上传明确APK、测试APK、reports、mapping/symbols路径，不上传keystore/工作目录。
- device矩阵为API26/29/33/35、API35 16KB与API37 Canary16KB x86_64。每个job校验实际API/页大小后运行APK内JNI/平台测试；超时/失败日志单独保留。未声称这些远程job已执行。
- `.github/workflows/baseline-profile.yml`：只读权限、关闭checkout credentials、显式Wrapper校验、宿主autoconf依赖；移除不精确的机器相关 .cxx 缓存。
- `.github/workflows/releases.yml`：同步标准variant路径，先验APK再重命名；编译job只读，只有独立publish job有contents:write。保持原有tag/manual入口及校验，没有触发它。
- 所有构建workflow继续 `gradle/actions/setup-gradle@v6`，显式 `validate-wrappers:true`；保留tracked wrapper.jar。
- `gradle/wrapper/gradle-wrapper.properties`：从Gradle官方端点读取并固定9.7.1分发ZIP SHA256。未重新生成Wrapper JAR。
- `rust-toolchain.toml`：声明 thumbv7neon-linux-androideabi，避免临时CI脚本与实际ARM32构建不一致。Cargo.lock和Rust实现未改，Cargo命令使用--locked。
- `app/src/main/cpp/CMakeLists.txt`：五个原有第三方tag固定为同一commit，并去除不适合commit固定的shallow选项；两份libarchive patch与所有许可保留。
- `.gitignore`忽略Python测试生成的 __pycache__，避免把缓存当源码提交。
- 新增 `scripts/verify_apks.py`、`test_verify_apks.py`、`verify_bytecode.py`、`run_emulator_tests.sh`。

## 实际验证

- Actionlint1.7.12、ShellCheck0.11.0、bash语法与git diff --check通过；检查脚本8个ELF正反例通过。
- P4主检查命令见README；首次完整检查 BUILD SUCCESSFUL，3m55s。最终资源/窗口清理后另有 final-check-build.log，报告其真实结果。
- Lint有warning，未开启全量warnings-as-errors、未为零告警而禁用规则。ObsoleteSdkInt与窗口宽度告警已针对源码处理；ChromeOsAbiSupport 对动态supportedAbis的判断由真实APK x86_64验证补充，未冒充缺少ABI。
- verify_bytecode对实际app/benchmark/core Android classes核对major61；不检查/限制在JDK25运行的宿主build-logic字节码。
- verify_apks根据真实AGP metadata严格要求四APK、版本/默认包名/min26/target37、Release证书、Native ABI与JNI导出；逐个64位ELF LOAD至少16KB，调用SDK zipalign和apksigner。最终SHA256见 JSON；它们对应本机APK，不是已发布产物。
- 三ABI C/Rust链接已实际执行；三ABI Clippy完成，Rust parser3项通过。设备Native运行覆盖ARM64五API，CI x86_64/ARM32设备运行不在本地通过范围。

## 未验证、风险、回滚

没有push，因此远程Linux Actions、GMD profile任务、artifact下载/传递和publish job均未执行；本地静态检查不等于远程CI成功。API37 Canary镜像固定日期是预览环境，正式API37镜像出现后需补验。现有 keystore/alias保持不变，未移走、更换或打印私钥。

Release仍声明四APK + mapping/native-symbols六附件；这是去Flavor后的原有发布行为同步。P9的“仅四附件、版本tag一致性、受限内部符号存储”尚未实施。CI diagnostics与Release payload继续保留符号/映射，Actions artifacts不能被称为私密存储；保存期限14天也不是长期内部归档。没有增加源码自定义zip/tar附件，GitHub自动源码归档逻辑未改。

回滚应同步工作流、Wrapper checksum、Rust targets、CMake pins与脚本；完整反向补丁见README。不要只还原workflow旧任务名而保留无Flavor应用。原有GIF/Unicode JNI缺陷、第三方升级、正式发布流程与用户数据完整迁移不属于本阶段已完成的修复。

Baseline Profile：connected API35 ARM64 `:app:generateBaselineProfile -PbaselineProfile.useConnectedDevices=true -Prelease` 实测 BUILD SUCCESSFUL（9m38s）；生成 baseline/startup文本已移至 evidence/profile-generated，不作为发布性能调优成果。两项 StartupBenchmarks 被跳过；联网UI存在超时，不能据此声称gallery完整旅程或性能对比通过。

最终验收：标准构建重试成功（2m10s）；移动资源后的初次增量链接缺少shortcuts，强制merge资源成功后重试通过。清理本地空限定目录并刷新Lint成功（54s），实际47项warning、0 error；保留2项IconXmlAndPng和1项ChromeOsAbiSupport，未禁用检查。诊断init脚本首次作用到included build失败，限定main build后通过，原始失败日志保留。
