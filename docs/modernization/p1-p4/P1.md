# P1：JDK25 / Gradle / AGP 工具链

## 修改

实际配置已满足 Gradle/JDK/API37 组合，无依据升级/降级会扩大风险，因此保留 Gradle9.7.1、AGP9.3.1、Kotlin2.4.10、KSP2.3.9、CMP1.11.1、Room2.8.4、Benchmark1.5.0-rc01。应用继续使用 AGP9 内置 Kotlin，四个 core 模块继续使用 Android KMP 插件和 CMP。

修改文件：

- `gradle/libs.versions.toml`：区分构建 JDK25 与 android-jvm17。
- `build-logic/convention/src/main/kotlin/AndroidApplicationConventionPlugin.kt`：显式 Java source/target17 与 Kotlin JVM17。
- `build-logic/convention/src/main/kotlin/MultiplatformLibraryConventionPlugin.kt`：Android target 显式 JVM17，不增加其他平台。
- `build-logic/convention/src/main/kotlin/com/ehviewer/Kotlin.kt`：移除对 JVM17 无效的 when indy 参数；保留其余编译配置。
- `benchmark/build.gradle.kts`：Java/Kotlin target17；可选 `-PbaselineProfile.useConnectedDevices=true`，默认 Linux managed device 行为保留。

宿主补装 autoconf2.73，解决 P0 的 Nettle `.bootstrap` 阻塞。没有改 Native 算法或 JDK 运行版本。

[Gradle JDK兼容矩阵](https://docs.gradle.org/current/userguide/compatibility.html)、[AGP9.3发行说明](https://developer.android.com/build/releases/agp-9-3-0-release-notes)、[内置Kotlin说明](https://developer.android.com/build/migrate-to-built-in-kotlin)提供版本约束；本轮真实编译是此仓库组合可运行的证据。

## 风险、回滚

JVM17 明确低于构建 JDK25；未来升级 JDK 不应自动改变 Android target。CI 的 verify_bytecode.py 从产出的 class 文件检查这一约束。Android26以上的实际核心 JNI 测试见 P3；Java/Kotlin所有业务流程并未穷尽。

回滚对应 convention/catalog/benchmark 配置；完整回滚检查与补丁见 README。回滚至 HEAD 会恢复隐式 target25 和旧 Flavor/宿主阻塞，不代表旧工具链更安全。没有提交或修改 Git 历史。

Baseline Profile：connected API35 ARM64 `:app:generateBaselineProfile -PbaselineProfile.useConnectedDevices=true -Prelease` 实测 BUILD SUCCESSFUL（9m38s）；生成 baseline/startup文本已移至 evidence/profile-generated，不作为发布性能调优成果。两项 StartupBenchmarks 被跳过；联网UI存在超时，不能据此声称gallery完整旅程或性能对比通过。

最终验收：标准构建重试成功（2m10s）；移动资源后的初次增量链接缺少shortcuts，强制merge资源成功后重试通过。清理本地空限定目录并刷新Lint成功（54s），实际47项warning、0 error；保留2项IconXmlAndPng和1项ChromeOsAbiSupport，未禁用检查。诊断init脚本首次作用到included build失败，限定main build后通过，原始失败日志保留。
