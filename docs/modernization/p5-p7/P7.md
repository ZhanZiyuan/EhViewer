# P7 — Rust Core / JNI 分层

采用最少的两个 package，保留 `app/src/main/rust` 和 `cpp` 顶层位置，不实施 P8 的 native/ 或 Kotlin 目录迁移。

| 进入本阶段路径 | 交付路径 |
|---|---|
| rust/src/parser.rs、parser/* | rust/core/src/parser.rs、parser/*（代码内容不变） |
| rust/test_data/* | rust/core/test_data/*（fixture 内容不变） |
| rust/src/img.rs、img/* | rust/core/src/img.rs、img/*；copy_region 改为 checked slice API，原指针适配位于 JNI |
| rust/src/lib.rs 中 parser 公共帮助函数/DTO | rust/core/src/lib.rs；EhError 对 JNI crate 可见 |
| 新迁移 hash/sort/gif/archive/fd | rust/core/src 对应模块 |
| rust/src/ffi/* | 原位置保留，新增 native.rs 兼容14个原 C JNI 方法 |

`ehviewer_core` 的正常依赖图没有 JNI/ndk/android_logger；宿主可以独立编译测试。libarchive/WebP 是平台无关 codec FFI，不等于 Android/JNI 依赖。NDK Bitmap/HardwareBuffer、裸图像指针适配、Java 字符串/数组/Buffer、日志初始化及异常映射集中在 root `ehviewer_rust`。没有新增 iOS/桌面 Gradle target；KMP/CMP Android 支持保持不变。

Root package 仍输出 staticlib；CMake/Corrosion 的 root MANIFEST_PATH 不需要搬移。保留 jvm/android/android-26 features、三个 ABI、`libehviewer.so` 和 JNI 类/方法名字。宿主 JNI 的 cdylib 是显式 `cargo rustc --crate-type cdylib` 测试输出，未加入 APK/产品平台。CMake 只生成空 `.S` link anchor，再链接 Rust 和固定版本的第三方库。

Release 从 immediate-abort 改为 unwind，std 开启 panic-unwind。所有 JNI 操作有结果/异常 guard，OnLoad 有独立 guard；Rust panic 被捕获，不向 JNI 展开。Release 宿主专门运行 panic/error/success 的 sentinel 回归。Bitmap/HardwareBuffer 的锁在正常、错误及 unwind 路径释放；Core region copy 验证边界，JNI 校验像素尺寸/格式。Android instrumentation 实际调用 detectBorder、hasQrCode、copyBitmapToAHB，在 API29+ 读取回拷像素。

CI 必要适配：host 安装 libarchive-dev/libwebp-dev；Cargo 命令选择 Core package 并运行 JNI guard 测试，Clippy 选择 workspace；新增真实 CMake 编译输入校验。没有重新改动发布附件规则或触发远程 Actions。setup-gradle@v6/JDK25、Android SDK、签名及 applicationId 沿用 P1–P4。

已验证与限制见 README、evidence：Core15测试、JNI guard1测试、fmt、三 ABI Clippy、Debug/Release链接和APK符号/16KB、Android矩阵。网络 parser3用例未运行，ARM32/x86_64只有编译/静态APK验证，未在运行时设备验证。回滚补丁恢复 workspace 前的 native 布局，保留 P1–P4 改动。
