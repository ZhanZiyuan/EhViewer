# P5 — 简单 C → Rust

基准：`feature/rusty`，HEAD/main 均为 `c5156a2de34e08fe9d11acd0f7552f6b8189a5db`；保留进入本阶段时 P0–P4 的未提交改动。按 hash、自然排序、GIF 的职责完成替换，交付保持未提交状态，未生成文档所建议的子提交。

| 原文件 | 实现 | 兼容性与有意修正 |
|---|---|---|
| `cpp/hash.c` | `rust/core/src/hash.rs` + `src/ffi/native.rs` | RustCrypto SHA-1 流式读取，8KiB 块，当前 fd 偏移至 EOF，小写 hex；复制 fd 但共享偏移，不关闭调用者 fd。负数/失效 fd 和读取失败成为异常，修复 C 的负 read 转无符号风险。 |
| `cpp/natsort/strnatcmp.c` | `rust/core/src/sort.rs` | 保留 Martin Pool 许可，标注 Rust 改写。数字长度、空白、前导零、大小写及 UTF-8 字节比较兼容；相同数字段一次推进。Android ARM 的无符号 char 与 x86 的有符号 char 行为显式保留。 |
| `cpp/gifutils.c` | `rust/core/src/gif.rs` + JNI 映射注册 | 保留 GIF87a/89a、旧控制块匹配、首个正常帧停止、signed-byte delay 规则；短缓冲使用饱和边界，不再 size_t 下溢。非直接或只读缓冲被拒绝，mmap/fd 错误有界返回。 |

以上 C 文件、排序头和旧 `ehviewer.h` 已删除；CMake 不再编译它们。Nettle 仍服务于 libarchive，不因 SHA-1 替换而删除。完整文件清单见 `files.txt`，实际 CMake 编译数据库见 `evidence/compiled-sources.json`。

已执行：原 C/JNI 宿主基线复跑；最终 Rust Release 动态库原 210 项 JNI 检查通过；最终 SHA-1 Android 测试验证标准摘要、空文件、多块及 fd 偏移。`native_differential.py` 对 signed/unsigned char 各 26,896 对名称、2,004 个 GIF 输入逐项比较旧 C 与 Rust，全部一致。Rust GIF 测试覆盖 0..4095 长度并在 ASan 下通过；故意不将已知会越界的 7 字节输入再交给旧 C 做“正常结果”比较。旧 C 的 ASan 越界记录保留在基线日志。

排序风险：原比较器对前导零等可返回相等；旧 qsort 没有稳定顺序保证，新实现对相等项保留原归档顺序。跨 ABI 的 UTF-8 顺序差异继续保留；本次没有擅自统一。GIF 的旧 signed-byte delay 行为继续保留，本次没有重新设计 GIF parser。

性能以 P6 的同优化级别宿主 JNI 工作负载记录为准。没有独立 Android SHA/GIF 微基准或真实漫画播放帧率测量，不声称这些性能已验收。测试命令、最终 Android 证据及回滚见 README。
