# P6 — archive.c → Rust/libarchive

旧实现依赖全局 mmap、条目数组、密码、20 个裸上下文和 4 个按最大文件尺寸分配的解码缓存。ctx_pool mutex 只保护分配/选择，`using` 和关闭流程仍可能与正在读取的上下文/ByteBuffer 冲突；错误路径和索引缺少一致的所有权约束。

新实现位于 `rust/core/src/archive.rs` 与 `archive/sys.rs`。第三方 libarchive 仍完成容器识别、压缩、密码算法和 ZIP 写入，未重写 libarchive/liblzma/Nettle。只声明实际使用的 3.x ABI，针对固定 3.8.7 头校验 `mode_t`、i64、ssize_t、指针与长度类型；Android 三 ABI 实际链接并打包验证。

| 原 JNI 方法（签名不变） | Rust 等价实现与错误边界 |
|---|---|
| openArchive(fd,size,sort) | 保留从文件偏移0建立映射及仅列举 regular/image 文件、大小写敏感扩展名。替换单个活跃会话；非法长度/坏包/限制错误返回0。 |
| extractToByteBuffer(index) | 原始 header 索引与排序后索引分离；跳页池复用。stored 数据独立 COW 映射，压缩数据逐页拥有。失败/null，不再越界访问。 |
| releaseByteBuffer(buffer) | 注册表持有原始 Java 对象及对应 Rust 所有权；释放原对象，同一对象重复释放 no-op；不依赖当前 archive 地址范围。 |
| extractToFd(index,fd) | 完整流式读写、重试中断、处理短写/错误/EOF，验证不超出声明大小；返回 boolean；保留调用者 fd 及其当前输出偏移。 |
| getExtension(index) | 同一扩展名白名单；非法索引成为 RuntimeException，旧 C 此处是未定义内存访问。 |
| needPassword() | 保留归档的 encrypted 标志，不因一次成功输入而改为 false。 |
| providePassword(String) | 正确把 UTF-16 Java String 转为 UTF-8（含非 BMP）；NUL/超长/错误密码失败。验证首个完整加密页面和认证尾，不遍历整本图集。错误候选不会覆盖已验证密码。 |
| closeArchive() | 移除当前 Arc；正在执行的读取保留会话，最后所有者 Drop 才释放上下文和源映射；输出缓冲独立存活。重复 close 安全。 |
| archiveFdBatch(fds,names,out,size) | 校验数组、数量、fd、普通文件、相对路径；RAII writer/entry、显式结束/关闭、短写及错误传播。当前输入偏移至 EOF 为条目大小，修复旧 st_size 与剩余内容不一致；失败抛异常。 |

线程与生命周期：只在选择/归还 reader、替换密码时锁状态，解压在锁外；最多4个并行操作，最多20个缓存 reader。Reader 只支持有依据的 `Send`，没有 `Sync`；libarchive README 明确不同对象线程安全、同对象需自行锁。本实现独占转移对象，不使用依赖 chdir/umask 的 archive_write_disk 系列。Raw pointer 仅在 sys/RAII 内部短暂使用；无 static mut，全局 JNI 状态为 Mutex<Arc> 和拥有数据的注册表。

防护：输入8GiB且不超过 isize::MAX/文件实际长度；单页256MiB；声明 regular 文件总展开64GiB；最多100,000 headers；名称和密码4096字节。拒绝绝对路径、`..`、反斜杠/盘符等危险名称；本实现只写传入 fd，不按归档路径写磁盘。最多128个/512MiB已发布缓冲；解压暂存和第三方 codec 窗口不计入此预算，所以不是进程峰值内存硬限制。源文件不得在会话/输出映射存活时被截断或修改。

已执行：13个归档以原 C 与最终 Rust 动态库运行同一个 JDK25 JNI 客户端，对比条目数、顺序、扩展名、长度、SHA-1/SHA-256；覆盖 ZIP/store/deflate、AES/ZipCrypto、TAR/gzip/xz、7z、RAR5 stored/compressed/solid/multiple 及4MiB页面。Core/Android 回归覆盖错误和 Unicode/emoji 密码、随机/反向跳页、fd输出、ZIP批写、close/reopen后缓冲、独立及共享会话并发、30轮/每轮8线程 JNI 生命周期及 fd 数量、声明超限和路径攻击。Core 另运行512个截断/字节翻转样本。详见执行日志。

行为限制：保留 `zip:ignorecrc32=1`，不声称所有 CRC 损坏都会被拒绝；依靠解码/长度/认证错误返回。JNI 为兼容仍只有一个活跃归档，Core 可创建独立会话；多个 Kotlin 读者不能借旧签名同时选择不同归档。超大合法页面、危险名称现在会失败，属于有意加固。

尚未验证：真实数 GiB 图集及长时间 Android 峰值 RSS、分卷/加密 RAR5、header-encrypted 7z、所有 codec bomb、Android 原生库全量 sanitizer。libarchive 原测试的某些压缩 RAR5 fixture 在本机 7zz 26.04 提示 Unsupported Method；libarchive C/Rust 与 Android 均作为实际支持路径验证，不声称 7zz 交叉解码通过。宿主 ASan 只覆盖 instrumented Rust/std 和系统拦截器，Homebrew libarchive 本体未重编译插桩，macOS LeakSanitizer 未启用。

同优化级别性能结果见 README/evidence；stored 页为生命周期安全多一个独立映射，有可测开销。回滚必须整体恢复 CMake、JNI/Core 和锁文件，不能只把 archive.c 链回去导致重复 JNI 符号。
