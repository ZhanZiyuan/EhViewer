# Shared favorite editing

This M5 slice adds the same Compose Multiplatform favorite dialog to gallery details on Android, Desktop and iOS. It loads the actual ten account categories, current gallery slot and original note, then adds, edits or removes a favorite through EhViewer's existing form protocol. A mutation sends one POST and only closes successfully after fresh bounded GETs confirm the category and note. An uncertain response retains the draft and requires an explicit reload before another mutation; cancellation never triggers an automatic retry.

`GalleryFavoritesRepository` reuses the current Ktor client, cookie store and real Rust decoders. A fetched editor is bound to its gallery, public/restricted host, hashed identity and session generation. Identity changes are checked at every request/decode boundary. A request-local mutation check also validates the cookies actually attached by Ktor after its State phase and before the engine sends; an account switch or a stale attached identity cannot mutate another account. The client-level hook captures no repository or account and leaves unrelated requests unchanged. Android borrows its existing client and `EhCookieStore`; test injection does not replace production cookie ownership. No plaintext credential, favorite state or request body is logged or persisted by the editor.

The Rust parser returns owned CBOR through the existing JNI/C ABI ownership contract. It requires one unambiguous favorite textarea, decodes entities without stripping literal note markup, normalizes line endings and enforces both the server limit and a 4,096 UTF-16-unit client cap. Documents and mutation responses retain the existing 8 MiB bound. Redirects cannot replay the form. Login, challenge, rate-limit, storage, invalid response and transport failures remain explicit. Confirmation GETs request `no-cache, no-store` so an older cached detail cannot stand in for the mutation result.

## Validation boundary

Seventeen new common repository cases cover exact forms, Unicode, cookies and host isolation, session replacement, uncertain mutations, reload, redirects, statuses, limits, body-read cancellation and malformed account/note data. The final-send case covers both a changed account and an account restored after Ktor read another identity into its outgoing headers. Actual Rust parser/C ABI tests and packaged JNI/Native product regressions cover the real decoder separately. The mandatory network suite floor increases from 118 to 135 without removing earlier cases; actual account product checks increase from three to four.

The first new body-cancellation test signalled before the response body was admitted, so its assertion failed. It now signals at the real `awaitContent` boundary while retaining the cancellation, closed-channel and single-POST assertions.
