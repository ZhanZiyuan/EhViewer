# Native macOS comic-folder selection

Normal Desktop execution exposed an empty Swing directory chooser. The macOS import path now uses AWT's native directory panel. The same native helper handles archive files and image-folder export, scopes `apple.awt.fileDialogForDirectories` to the open panel, restores its previous value in `finally`, and rejects overlapping requests from a nested EDT modal loop. It uses public AWT APIs and the directory switch present in the actual packaged JDK25 source and [OpenJDK's implementation](https://github.com/openjdk/jdk/blob/jdk-25-ga/src/java.desktop/macosx/classes/sun/lwawt/macosx/CFileDialog.java). No OpenJDK implementation is copied and no internal Java package is accessed. Windows/Linux retain their existing directory chooser.

For image-folder export, macOS selects an existing parent; the shared exporter exclusively creates its suggested child folder. An existing child fails without replacement. Users can choose or create another parent in the native panel. Compressed archives retain their filename save dialog. Common snapshot ownership, byte validation, cancellation, bounded copies and no-overwrite behavior remain unchanged.

The actual packaged application imported the owned two-PNG directory, displayed real page-2 pixels in the common reader and exported both ordered PNGs with identical source hashes. Repeating export to the same parent reported a recoverable error and retained every output byte. Cancelling export returned the localized cancellation message; cancelling folder import retained both library entries. Original inputs and library files remained unchanged and no private `.export-*` directory remained. Subsequent native file selection accepted the original CBZ; reading its previous-build progress is separately waiting for macOS Keychain authorization, confirmed by the owned process sample. It is not counted as a completed compatibility check.
