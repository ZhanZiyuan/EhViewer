# Local comic archives and the shared reader

This M4 slice connects an actual file import to the existing Compose Multiplatform reader. Desktop and iOS share the library list, password form, image navigation and per-book reading state. Desktop supplies the native file dialog; iOS supplies a Kotlin/Native UIKit document picker. Android keeps its original SAF/archive reader and receives a regression of the same portable JNI contract. This does not complete M4 or final platform acceptance.

`FileArchiveLibrary` streams a selected file into a new private directory, computes SHA-256, flushes its payload and metadata, validates the copy through Rust, then atomically publishes the directory. Duplicate content keeps the existing book and title. Cancellation and failed publication remove only the import's own staging directory. The original selected file is never modified. Opening a book verifies its actual bytes again. A live native lease prevents deletion of its backing file, and application shutdown waits for admitted reads before unloading Windows native libraries. No existing Room schema changes.

The C ABI owns bounded archive sessions and independent result buffers; JVM/Android JNI and Kotlin/Native use that same implementation. It retains EhViewer's original Rust `ArchiveSession`, natural ordering, ZIP/RAR/7z handling and password validation. Paths are private absolute regular files, result copies are bounded to 32 MiB and the registry admits at most eight sessions. Invalid/stale handles and cross-type handles are rejected. Exceptions exposed to the UI do not contain private paths or passwords. Passwords are not saved in library metadata or reading state.

`ArchiveGalleryContent` adapts native page bytes to the existing reader through validated local document URIs. It makes no HTTP request and rejects foreign book identities and page indexes. Reading state uses a separate vault directory for each content hash, so local books do not overwrite online gallery history or service tokens.

## Apple dependencies and licensing

Using archive extraction exposed the missing libarchive link in the earlier parser-only Apple spike. The iOS build now compiles original third-party libarchive and liblzma sources into separate ARM64 simulator/device static libraries. It uses the same immutable libarchive 3.8.7 and XZ 5.8.3 commits already selected by Android, checks the downloaded source SHA-256, checks the resulting CPU, retains source provenance and original notices, and links public SDK zlib/iconv and CommonCrypto support. It does not depend on the local Animeko tree or Apple's private libarchive/liblzma libraries. Upstream C sources are third-party inputs, not new maintained implementation files.

The libarchive notice describes its BSD terms and per-file exceptions. XZ's original notice identifies liblzma as 0BSD; XZ command-line programs and their GPL components are disabled. This is not a claim that the complete application SBOM or release license audit is finished. The simulator app includes the original notices; final IPA packaging must retain them as part of M6.
