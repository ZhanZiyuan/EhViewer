# Shared gallery link actions

The common CMP detail screen now offers **Copy link** and **Open in browser**, with English, Japanese, Simplified Chinese and Traditional Chinese feedback. The repository supplies the validated canonical HTTPS gallery URL; cookies and credentials are never included. Actions run only after a user click. Recoverable clipboard/browser failures remain on the screen and can be retried; cancellation propagates. Feedback is scoped to the displayed URL, exposed as a polite accessibility live region and cleared when the detail screen is reopened.

`GalleryLinkActions.kt` uses Compose platform clipboard and URI services. The pinned CMP1.11.1 artifacts have no common plain-text `ClipEntry` factory, so the existing platform-backed `ClipboardManager` is isolated behind one documented deprecation suppression. The actual cached API was inspected; dependencies were not upgraded. See the primary [Compose platform sharing documentation](https://kotlinlang.org/docs/multiplatform/compose-share-feature.html). Android supplies its existing Custom Tabs adapter through `rememberGalleryBrowserHandler`, preventing an E/Ex App Link from simply reopening EhViewer. The original Android helper retains its empty-URL and missing-browser behavior.

Reference decision: Animeko `docs/contributing/architecture.md:112–153` informed the separation of common UI and platform services. Targets are `app/shared/.../GalleryLinkActions.kt`, `GalleryDetailScreen.kt`, Android `SharedGalleriesScreen.kt` and `UrlOpener.kt`. EhViewer retains its gallery repository, original Android browser implementation and existing session ownership. No Animeko implementation, resources, scripts or dependencies were copied; no precise licensed reuse was required.

Local acceptance used the same frozen nine implementation files throughout:

- Mandatory Android unit/lint/Debug/AndroidTest/four-ABI Release/benchmark checks and formatting passed,498 tasks. The same APK pair passed all48 existing instrumentation cases on both API36 phone and tablet, with zero failures/skips. The existing favorite integration case additionally verifies real native clipboard sentinel replacement, recoverable one-shot failure/retry, lifecycle feedback reset and the actual production Custom Tabs URL/session intent. Its owned ActivityMonitor cancels the intent after inspection; this is not a claim that the Android browser rendered.
- Standalone Desktop tests, formatting and actual distributable passed,83 tasks. An independently identified test app with a fresh profile displayed real public gallery details, copied the correct URL, opened the actual system browser and cleared old feedback after returning to search and reopening. A disposable Finder field independently read back the copied URL without navigating. The original denied vault/profile was not read or copied. The test app was quit normally.
- iOS Simulator packaging, unsigned device linkage and formatting passed,84 tasks. The actual startup/lifecycle verifier passed two cold starts and Native network140/data69/reader52 cases with zero failures/skips. Normal iPad interaction opened the same real public gallery, showed successful copy feedback, launched Safari with the exact gallery URL and pasted that URL into an emptied native address field. Reopening the detail screen cleared the previous feedback. The owned Simulator was shut down with its data preserved. This is Simulator evidence, not signed-device acceptance.

The public reference-book gallery used for manual checks was `https://e-hentai.org/g/4298340/0bace2571c/` (Space Battleship Yamato Official Fact File No.37). No account mutation, rating or authenticated content was used. Native clipboard readback was successful on Mac and iPad; the Android test separately proves sentinel overwrite. Initial remote text-field setters and an accessibility text click on iOS Paste did not activate their controls; a normal coordinate click on the visible native Paste item succeeded. Tool focus/latency failures are retained, not treated as product performance or keyboard acceptance.
