# Desktop native browser session handoff

This M3 slice connects the existing shared CMP Account controls to real desktop WebKit, WebKitGTK and WebView2 windows. Search, details and reader remain the same shared Kotlin/CMP implementation. Normal browsing uses real service responses; synthetic cookies exist only in explicit regression mode.

The Kotlin platform adapter calls Rust through JNI on Unix desktops and the existing owned-buffer C ABI on Windows. Rust owns a bounded private pipe to a native GUI companion, its main-thread event loop and process lifetime. Kotlin does not spawn processes or implement a second browser protocol. The companion uses an isolated nonpersistent store, the configured network User-Agent, system TLS, official service origins and the exact HTTPS Cloudflare challenge origin. Wry's portable navigation callback does not expose frame identity, so that challenge origin is allowed for navigation as well as subframes; its cookies are never transferred. Popups, downloads and permission requests are denied. No page evaluator, injected JavaScript or CAPTCHA solver is introduced.

Cookie transfer retains native domain spelling (including the leading dot), path, Secure, HttpOnly and expiry. Direct native cookie APIs avoid Wry's normalized domain accessor. The existing common transaction validates identity, scope, bounds and generation before one atomic encrypted-vault commit. Back or window closure discards the private store. Native handles have a separate numeric namespace, a four-process limit, bounded reads/deadlines and stale/double-close rejection. The parent library starts no background Rust reader thread: per-call Windows FFM arenas can close safely while the application keeps its main-thread DLL owner until all browser processes close.

`prepareNativeBrowser` compiles the actual distribution CPU with locked Cargo inputs and retains Cargo's executable receipt and SHA-256. The product resource merge keeps existing JNI/C ABI libraries and notices. Unix `jpackage` drops the executable bit of additional resources; the distribution task restores and checks that bit before DMG/image consumers run. Starting the browser after Compose commits also prevents an early native failure from being overwritten by the initial UI snapshot.
