# Shared detail comments

The common Compose details restore the original two five-line comment cards between tags and previews. The separate comment route uses the actual service `hc=1` request through the existing authenticated, bounded Ktor transport and Rust gallery decoder. Failed refreshes retain the prior comments and expose an explicit retry. The detail-owned comment list, loaded result and scroll position survive reader navigation and route reentry. Selection/copy, HTML links, same-gallery reader links and comment anchors use shared UI; executable or credential-bearing links never reach a platform opener.

The existing Rust DOM produces portable styled text/image runs while preserving the original HTML field and backwards-compatible Kotlin model defaults. Inline images use the existing bounded image transport, decoder and 16 MiB cache; arbitrary external image hosts do not gain session cookies or unrestricted fetch access. No ABI entry point changes, new HTML parser dependency or Animeko implementation is introduced. The existing pinned quick-xml gains its HTML entity feature. Rendered output is bounded before inherited addresses are cloned: 1 MiB per comment and 8 MiB for the complete gallery. Two adversarial regressions first failed without those limits and pass with the fix.
