# Shared application language settings

Search, details, previews, account/favorites, downloads, the local library, both readers and settings use the same CMP string resources. English, Simplified Chinese, Traditional Chinese and Japanese each have 180 keys with identical format arguments. The picker uses language autonyms and a System option; valid unsupported saved tags remain visible and are never silently replaced. Only resource lookups are keyed by language, preserving common navigation, search and reader state.

`AppLanguageStore` separates nonsecret preferences from locale application. Desktop/iOS use the existing atomic DataStore in a separate file, without a keychain request. Unknown schemas, malformed tags and corrupt files reject reads/writes/reset while preserving bytes. Cancellation propagates; a committed write followed by an application failure requires reloading the saved choice before another selection. Existing preferences, databases and sessions are retained.

Android retains the original AppCompat per-app locale and persistence rather than introducing a competing store. Desktop captures its startup system locale and applies the selected resource locale through the public JVM API. Kotlin-only iOS uses public Foundation preferences, retains ownership and the original app-domain language value, and restores that value for System. It never snapshots a global fallback into app defaults, which would pin System to a previous OS language. Existing external language settings are preserved when restoring the backup. CMP 1.11's language/region resource selection is handled by an independent Chinese script-to-region adapter; explicit Hans/Hant takes priority over region. No internal Compose API is accessed.

Simulator packaging now includes the actual aggregated CMP resources under the path required by the runtime reader. The resource package is explicit, so repository and standalone Desktop roots generate the same namespace. Apple bundle declarations list the four languages and continue to support iPhone/iPad. Device compilation remains unsigned; it does not establish signed-device execution or a directly installable IPA.

The first phone run exposed missing Android assets and terminated at the existing archive-sharing regression; no complete pass is claimed for that run. The CMP convention now enables Android resources on an existing Android-KMP target, as required by the [official setup](https://kotlinlang.org/docs/multiplatform/compose-multiplatform-resources-setup.html#resources-in-the-androidlibrary-target). The callback also preserves standalone Desktop builds, where the Android plugin is absent. APK validation requires all four real compiled language payloads and compares every decoded string with the same-source XML. It records their hashes without requiring generated files from another runner. Missing, stale, malformed and duplicate data are rejected. The complete phone/tablet suites remain required.
