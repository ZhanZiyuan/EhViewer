# Native Linux AppImage candidates

The existing shared KMP/CMP application is packaged as genuine type-2 AppImages for x86_64 and aarch64. Each image contains the actual corresponding jpackage/JDK, Skiko, Rust and browser executable. A relative `AppRun` link enters the real application launcher; no authored shell launcher or renamed ZIP is used. The original source-derived PNG supplies the desktop icon and `.DirIcon`, and the desktop entry launches the application normally. Common UI and business implementation remain shared.

The Kotlin packager uses fixed official [type2-runtime 20251108](https://github.com/AppImage/type2-runtime/releases/tag/20251108), source commit `dd6cebedcbddde9c82f89b011e8e1d40b6e43868`, and verifies each architecture's published SHA-256 and runtime offset before appending real zstd SquashFS. The embedded source record binds version/code, checkout SHA/dirty state, CPU and runtime digest. The portable verifier checks ELF CPU/type/entry, type-2 marker, pinned runtime prefix, SquashFS4 bounds/compression/time and trailing padding. See the official [architecture](https://docs.appimage.org/reference/architecture.html) and [AppDir specification](https://docs.appimage.org/reference/appdir.html). No AppImage/Animeko implementation source is copied; the official compiled runtime and exact upstream license are third-party inputs. Complete embedded-dependency license/SBOM acceptance remains open.

Packaging uses owned temporary directories, rejects escaping or absolute links and special files, and compares every extracted file, mode and internal link to the actual package input. Native bytes must match the original executed image receipt. The real AppImage entry then executes once through extraction and once through default FUSE. Both executions must match the inspected bundled JVM hash/version/CPU, draw Compose frames and pass gallery5/account4/history3/archive9/language4, Rust100 and native-browser ownership. FUSE execution records its actual filesystem type; its owned mount must disappear within a bounded lifecycle check before temporary cleanup. The original image's two launches, JNI4170, thirteen archives and all prior ARM64 inventory checks remain mandatory.

Existing `rust_host` x64 and `desktop_linux_arm64` native runners produce these candidates on `ubuntu-latest` and `ubuntu-24.04-arm`. Their existing artifact roles retain the exact tested AppImage and receipts, without an extra download/catalog role. The strict ten-candidate staged preflight repeats portable format inspection and verifies clean same-source version/CPU, original image/JNI receipts, both actual entry modes, render backend, FUSE release and final-copy SHA. It still declares final eleven-asset delivery, full product P0 and publishing incomplete. The production `releases.yml` expansion remains separate work.
