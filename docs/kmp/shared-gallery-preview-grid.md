# Shared gallery preview grid

This M5 slice replaces the detail screen's plain page rows with real image thumbnails. Detail and the paged preview browser use the same common Compose Multiplatform cells, bounded decoded-image cache and actual page-token navigation. Android, Desktop and iOS share the implementation and Material3 theme, including the existing dynamic-color integration.

The reference is EhViewer `v1.15.10`, commit `423b8af13632896b55780783b54b5f720ec4c9dd`: `app/src/main/kotlin/com/hippo/ehviewer/ui/screen/{GalleryDetailContent,GalleryPreview}.kt`, `core/ui/src/commonMain/kotlin/com/ehviewer/core/ui/component/Card.kt` and `app/src/main/kotlin/com/hippo/ehviewer/ui/tools/CropDefaults.kt`. The common targets are `GalleryDetailScreen.kt`, `GalleryPreviewGrid.kt`, `GalleryPreviewImage.kt` and `GalleryPreviewScreen.kt`. Cells retain the original 0.67 image ratio, transparent card border, number caption, 8dp spacing and crop range 0.5–0.8. Sprite cropping uses the individual tile dimensions and the existing validated source region. Phones use three columns; surfaces at least 600dp wide adapt toward 128dp cells, capped at twelve columns. This is an incremental default-layout adaptation: the original custom thumbnail-column preference, complete detail pagination and full pixel equivalence remain further work. No Animeko implementation, resources, scripts or dependency set were copied.

The detail and browser share one 16MiB image cache for the current gallery. A single active fetch/decode and existing cancellation/error behavior remain enforced. Returning from the reader reuses decoded thumbnails. Initial detail positions are validated before creating grid keys; malformed windows cannot manufacture a page/token pair. The browser still fetches and validates real subsequent preview windows, including a short last window.

Two new Desktop scene cases exercise actual bitmap painters, pointer clicks, source-region crop policy, original cell ratios/spacing and 320/411/1280dp widths with 1.0/1.8 font scales. They also verify one image load for cells sharing a URL. Existing Android flows retain real Rust parsing, original-image/GIF/WebP reading, exact download Range/referer request counts, pause/resume and offline Room progress. Only fixture thumbnail URLs were separated from downloaded page-image URLs, matching the site's distinct resources; existing request-count, cancellation and offline-network assertions were preserved.
