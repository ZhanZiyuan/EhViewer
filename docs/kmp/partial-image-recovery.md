# Resuming the current downloaded image

Current status: local Android/phone/tablet/Desktop/Native acceptance below is complete; the new feature commit still requires its own hosted CI. Previous media repair `cc49709f2` passed all 12 checks in [full CI41280654439](https://github.com/ZhanZiyuan/EhViewer/actions/runs/41280654439). Earlier pending statements below preserve their original validation time.

The common download queue can retain the current image's validated prefix across pause and process restart. Completed image rows keep their original publication path. The production Android download manager is unchanged; Desktop/iOS use the existing common Room queue, and explicit Android integration exercises that same queue and CMP reader.

Only a strong quoted ETag and a bounded positive Content-Length enable a checkpoint. Requests use identity encoding, an exact suffix Range and If-Range. A 200 response replaces the prefix. A 206 response must describe the exact remaining suffix of the same representation and final target; malformed ranges, changed targets/validators, transformed bodies, unsolicited ranges and 416 responses cannot append. Servers without resumable validators retain bounded full-image downloads. This follows [RFC 9110, If-Range and partial content](https://www.rfc-editor.org/rfc/rfc9110.html); it does not claim that every live image node supports ranges. Redirect limits, image-host/HTTPS checks, cookie isolation, safe errors and session-generation checks remain enforced. No signed image URL is persisted: metadata contains source/final URL SHA-256 fingerprints, the page token, ETag, length and chunk hashes.

Private `partial-<index>.data/.cbor` files are separate from committed pages and their existing temporary names. One storage owner serializes page admission without holding its IO mutex across HTTP. Fixed 1 MiB hashes validate the published prefix on reopening. Appending rehashes only a short final chunk plus newly received bytes. Data is flushed before atomic metadata publication; an interrupted unpublished tail is truncated only after prefix verification. Reset publishes empty metadata before truncating old data. Reaching the declared length alone is not completion: verified EOF publishes a separate completion flag. A complete checkpoint remains until the normal image file, Room page row and visible count have committed. Pause can persist its admitted worker's received tail after setting PAUSED, and resume waits for that worker to join. Deletion waits for the admitted owner and removes only that task's private directory. Corrupt checkpoints remain an explicit storage failure and can be deleted through the existing download UI; committed pages are preserved.

This is an application-owned single-queue design. It does not introduce a cross-process file lock or claim power-loss durability beyond the existing flushed files and atomic filesystem operations. Full-image allocations retain the 32 MiB bound; measured whole-process memory/performance and all M4 acceptance remain outstanding.

Reference boundary: read-only Animeko `docs/contributing/architecture.md` and its existing `app/shared` platform/storage separation inform the boundary only. Adopt shared state and platform IO interfaces, adapt them to EhViewer's per-page HTTP validators, Room queue and image reader, and reject video/BT transfer implementations and dependencies. Targets are the domain checkpoint contract, `core/network` image transport/queue and `core/data` private files. No AGPL implementation, resource or script is copied; the existing Okio version supplies hashing and IO, with no dependency upgrade or Rust ABI change.

Ten common network regressions cover cancelled streaming bodies and exact resume, 200 replacement, weak/missing validators, source/final target changes, invalid/multipart ranges, truncated/excess bodies, EOF, redirects/session/cookies, status/storage classification, encoding and size limits. Seven real-file/Room regressions cover restart and partial chunk merging, failed metadata publication, corruption preservation, interrupted reset, malformed/oversized metadata, deletion ownership and cleanup after a page commit interrupted before checkpoint removal. Recovery verifies the committed image before removing that obsolete checkpoint; normal pages incur no extra image hashing. The verifier requires both new suites on their applicable hosts. Android's existing download interaction is extended to pause mid-image, reopen the queue/database, require the actual conditional range, finish, remove the checkpoint and reopen offline in the shared reader.
