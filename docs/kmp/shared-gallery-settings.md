# Shared gallery appearance and reader settings

The common CMP settings page exposes system/light/dark appearance and the existing paged/continuous and reading-direction preferences on Android, Desktop and iOS. It uses the same business screen and Material theme on each platform. This is a prepared product slice; M3 and the full settings P0 remain incomplete.

Android reads and atomically updates the original `Settings.theme` DataStore key; its existing AppCompat/system-night collector remains authoritative. Reader controls use the existing `ReaderStateStore` and original Android adapter. Desktop and iOS persist appearance through a separate real OS-backed vault directory, with the existing Windows and Apple implementations. Cookie records are not used as preference payloads. The versioned record is bounded, invalid/future records are preserved, cancellation propagates, and failed persistence does not update the UI as if it succeeded. Settings errors have explicit retry; concurrent clicks are guarded.

The read-only Animeko reference is `docs/contributing/architecture.md:112–153`, which describes shared UI/data and platform ownership. The targets are `app/shared/.../GallerySettingsScreen.kt`, `settings/GalleryAppearanceStore.kt`, Android's `AndroidGalleryAppearanceStore.kt`, and the existing Desktop/iOS factories. Adopt that boundary, adapt it to EhViewer's real DataStore/vault and reader contracts, and reject the Animeko dependency graph and implementation. No AGPL code, resources or scripts are reused; the implementation is independent Kotlin.
