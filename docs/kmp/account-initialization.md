# Shared account initialization

M3 remains in progress. The shared CMP Account screen now loads the real forum profile, ten favorite categories, image-limit/news initialization cookies and restricted-site availability through one KMP repository. It offers explicit public/restricted site selection only after actual account validation. Identity/site changes clear the search/detail selection, and sign-out returns to the public site. Android now opens the same common CMP search, detail and reader through an additional production drawer destination; its existing account flow and storage remain authoritative. Full account UI convergence and durable shared settings remain unfinished work.

The real Rust forum/profile/config parsers are reused through owned CBOR buffers, JNI and C ABI. No second HTML parser, mock production profile, JavaScript or platform-specific account UI is introduced. Three additional account-decoder assertions execute in explicit desktop and iOS startup regressions; the original three gallery/image checks remain independently mandatory.

## Session behavior

Refresh starts with an authenticated snapshot and stages all response cookies privately. Trusted HTTPS origins, port 443, six-hop redirects and bounded documents are checked before contact. Profile links require the original forum profile URL form. The existing public session changes only after a successful atomic vault write. Failed profile/config requests, cancellation and failed writes preserve the prior session. Generation checks before every request/redirect and before commit prevent logout or a newer login from being overwritten or followed by additional old-identity requests.

Restricted-site initialization follows the service's actual Ex → forum remote API → Ex callback flow. E-Hentai credentials are never copied into Ex cookies. An anonymous HTTPS observation reproduced that redirect shape, with queries omitted from retained evidence; it did not establish authenticated access. The original project's `EhEngine.getUConfig` also retries the first redirected Ex document once. This implementation retries only one malformed Ex document, requires a valid final config plus Ex-scoped identity, and rolls back partial restricted-site cookies on failure. Public profile/config success remains usable when Ex is unavailable or its network check fails.

Cookie replacement normalizes only the domain key's case/leading dot, preserving host-only matching, path, Secure, HttpOnly and absolute expiry. Existing stored-cookie schema 1 remains readable; snapshots are not converted through new Max-Age calculations. No Android database or existing data is deleted or reset.

Account/service requests and redirects require port 443. Image transport preserves legitimate H@H configured ports **1024–65534**, in addition to 443, only on the existing trusted H@H host suffix and with system HTTPS validation and no account cookies. The [service's H@H documentation](https://ehwiki.org/wiki/Hentai%40Home) documents that range. Regression cases cover both port boundaries, an intermediate image port, rejected service/non-H@H ports and continued identity isolation; no custom-port restriction is imposed on the user's H@H settings.

## Android product integration

`GalleryLibrary` lets the common CMP search/detail/paged/continuous reader use Android's application-owned `noRedirectKtorClient`. `AndroidGalleryLibrary` retains the real CookieManager, User-Agent, Cronet, DNS and network preferences; leaving the screen cancels its requests without closing the borrowed application client. Returning to Android account settings uses the original account destination. Changing the site or sign-in state creates a fresh gallery scope. The new drawer item is appended, preserving persisted launch-page indexes and all existing destinations.

The adapter writes only real decoded gallery metadata to the existing history before reading. `AndroidReadingState` uses the original Room progress rows and atomic DataStore preferences. Legacy index-only progress is resolved to an actual page token by the common reader; missing gallery parents fail without fabricated rows. The existing database schema, both migration paths and legacy reader APIs remain intact. Continuous-vertical preferences are preserved. No shadow database or destructive fallback is introduced.
