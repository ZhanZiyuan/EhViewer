# Shared Downloads search and empty state

The common Downloads page adopts v1.15.10's floating 56dp Material 3 search bar, original 120dp Big.Download artwork, primary tint, headlineMedium and existing four-language empty text. Phone navigation opens the common drawer; wide windows keep the rail. System Back still returns to the preceding page. The bar remains available during loading and storage failure. Empty storage is never claimed after a failed queue load.

Search submits a local, case-insensitive title filter. Editing is a draft until Search/IME submission; queue updates respect the applied filter and starting a search resets its viewport. Search never issues site requests or mutates hidden entries. Existing pause/resume/delete/offline-read operations retain their actual gallery identities and committed page counts.

Reference: this repository's v1.15.10 `ui/screen/DownloadsScreen.kt`, `SearchBarScreen.kt`, `core/ui/icons/big/Download.kt` and `core/i18n` strings. Targets are the existing common Downloads screen, navigation container, icon and locale resources. The icon and translations come from EhViewer itself under its existing license. No Animeko implementation, asset or dependency is copied.

This slice does not claim complete Downloads parity: labels, the user-selected grid mode, original scroll-away behavior and bulk selection still require implementation and actual visual acceptance. M5 remains open; version 1.15.10 / 180074 and Draft PR15 are unchanged.

Shared Desktop 119, Android Host 67 and Native 79 tests pass, together with Android unit/lint/build, both iOS application links and macOS packaging. Phone and tablet each pass all 53 tests without skips on the identical final APK pair. The product APK remained byte-identical during the test-only capture/refresh corrections. Original three-request assertions, routes, saved-prefix, byte-range, cancellation and offline-read checks remain intact.

Normal iPhone light/dark and the same application on iPad Chinese light portrait/dark landscape were reviewed and captured; the selected Downloads page/theme survives rotation and portrait was restored. Normal packaged macOS Chinese light/dark navigation and layout pass. Automated Mac typing did not change the field and remains unverified. Raw frames and source/APK/JAR hashes are retained under `build/kmp-work-logs/ui-downloads-*20261106/`. These different viewports and controlled download fixtures are not pixel-parity goldens.

Earlier functional passes remain recorded, but some screenshots showed the preceding frame and are not accepted. In both filter directions, the updated capture requires new text pixels, removal of the preceding text pixels and the matching actual controls before saving the unedited full bitmap. Final phone and tablet frames were visually reviewed. One subsequent tablet run exposed an existing comments-test race: an unchanged footer was accepted before the third request. The test now waits for unique refreshed response text while retaining the three-request and route assertions; the failed run remains preserved. No product workaround, relaxed deadline or skipped test was introduced.

## Download cards and local previews

The next common card uses this repository's v1.15.10 `app/src/main/kotlin/com/hippo/ehviewer/ui/main/DownloadCard.kt` as its visual reference: original cover ratio, card height, titleSmall, uploader/disowned alpha, rating, category chip, play/pause/done controls and wavy progress. Wide windows gain adaptive columns; large fonts increase card height while keeping a readable cover/text split. Long press, secondary click and Shift+F10 expose the real actions. The phone's one-column layout and all platforms use the same Compose implementation and theme. This is a partial restoration, not an assertion of pixel equivalence or complete Downloads interaction parity.

New-platform tasks retain only public uploader/rating/category metadata. Room's additive v1-to-v2 migration preserves old task order, state, page hashes and image files; metadata is a nullable CBOR blob. The Android download database, workers and existing migrations are unchanged. The migration test opens the actual v1 schema, reads its committed page, updates metadata and verifies both after reopening.

Previews read an already committed local first page on the shared queue, or an existing Android thumbnail/cache/loose first page. They never start a network request or modify downloaded images. Identity includes both gallery ID and token, input is bounded to 32 MiB and decoded images retain the existing serialized 16 MiB LRU. Legacy Android archives without a retained thumbnail or loose first page can report unavailable; archive extraction is not borrowed from the active reader. Queue tests verify source counts, identity mismatch, cancellation and image preservation. Favorite notes, cookies and account API credentials are excluded from the metadata model.
