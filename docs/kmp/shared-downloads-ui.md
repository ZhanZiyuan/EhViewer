Search never issues site requests or mutates hidden entries. Existing pause/resume/delete/offline-read operations retain their actual gallery identities and committed page counts.

## Download cards and local previews

This is a partial restoration, not an assertion of pixel equivalence or complete Downloads interaction parity.

New-platform tasks retain only public uploader/rating/category metadata. Room's additive v1-to-v2 migration preserves old task order, state, page hashes and image files; metadata is a nullable CBOR blob. The Android download database, workers and existing migrations are unchanged. The migration test opens the actual v1 schema, reads its committed page, updates metadata and verifies both after reopening.

Previews read an already committed local first page on the shared queue, or an existing Android thumbnail/cache/loose first page. They never start a network request or modify downloaded images. Identity includes both gallery ID and token, input is bounded to 32 MiB and decoded images retain the existing serialized 16 MiB LRU. Legacy Android archives without a retained thumbnail or loose first page can report unavailable; archive extraction is not borrowed from the active reader. Queue tests verify source counts, identity mismatch, cancellation and image preservation. Favorite notes, cookies and account API credentials are excluded from the metadata model.

The Android integration test removes only its owned fixture's history/gallery row before offline reading while retaining all original image, range, route, request-count and progress assertions.
