# Shared adaptive search covers

The production shared search screen now shows cover, title, page count, language and available rating in one common CMP card. An adaptive320dp minimum column width keeps compact phone windows in one column and uses the same cards in wider tablet/Desktop layouts. The existing1040dp content-width limit, search/filter/cursor behavior and stable gallery keys are retained. A page-owned cache survives detail navigation, resets with a new result/session and admits one image download/decode at a time. A missing or failed cover leaves the gallery readable/selectable, with an explicit retry for request/decode failures.

`GalleryRepository.cover` reuses the existing client, cookie jar, request timeout, HTTPS/redirect/byte bounds and image transport. It preserves the existing E/Ex JPEG/WebP cover-key mapping, including encoded paths/query parameters. Invalid identities, traversal keys, credentials and non-cover initial destinations fail before network access. The portable session store retains its strict service-host identity-cookie policy and excludes CDN identity cookies. Android continues borrowing its original application cookie store; that policy is not replaced. No extra production client or fabricated image/page token is introduced.

Published covers have a maximum512px edge and at most1MiB RGBA. Android samples before its final resize and recycles the temporary bitmap. Desktop/iOS validate encoded dimensions and close temporary Skia data, codec, image, pixmap and bitmap owners before publishing the small Compose bitmap. The cache retains at most16MiB; visible cells additionally own their bounded displayed images. Full reader image/animation decoding stays unchanged. Existing packaged GIF/WebP regressions also exercise each format's cover first frame on actual native runtimes, preserving all original animation assertions and the original two-format count.
