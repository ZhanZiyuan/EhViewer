# Open desktop comics in the shared reader

The normal desktop entry accepts `EhViewer --open <comic-archive-or-image-directory>`. It opens the shared local library, copies the selected input through the existing Rust-backed private archive/directory importer, then uses the same CMP reader as online and downloaded comics. Import progress, cancellation, password prompts, recoverable failures, export and reader progress retain their existing paths. Returning to the library does not reopen the input; a failed or cancelled request leaves manual import available. This adds an explicit command-line entry; OS file associations and drag-and-drop are not implemented by this slice.

The behavioral reference is Android v1.15.10, `423b8af13632896b55780783b54b5f720ec4c9dd`, `app/src/main/kotlin/com/hippo/ehviewer/ui/MainActivity.kt`'s `ACTION_VIEW` file/content reader dispatch. Desktop paths require the platform's real filesystem handling and private-copy ownership. Targets are Desktop `DesktopMain.kt`, `DesktopDocument.kt`, `GalleryApplication.kt`, common `GallerySearchScreen.kt` / `ArchiveLibraryScreen.kt` and their regressions. No Animeko code, resources or dependencies were copied; no new third-party implementation is vendored.

Three actual Compose scene tests cover one-time import/password/return/disposal, failed input/manual recovery and cancellation/window disposal. The existing real Desktop Rust archive regression additionally checks Unicode file/directory arguments, invalid arguments, natural page order and pixels, duplicate import, missing/corrupt inputs and preservation of the valid library. The first test run used English labels on a Chinese host and failed; corrected tests read the actual localized resource labels. A combined Gradle invocation exposed output-ownership validation between packaging and an externally selected regression library; the checks were run sequentially without weakening that validation.
