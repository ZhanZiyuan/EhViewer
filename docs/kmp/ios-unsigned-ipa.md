# Optimized unsigned iPhone and iPad IPA

The existing Kotlin/Native + UIKit application now has a real Release bundle and `packageUnsignedIpa` task. It links the production arm64 iOS executable, copies the actual device CMP resources, compiles Apple device icons, merges device-platform metadata and retains the existing licenses. The ZIP contains `Payload/EhViewer.app` with an executable 0755 launcher and regular 0644 resources. Its name is derived from the unchanged Android version authority: `EhViewer-1.15.10-arm64-unsigned.ipa`. It has no developer signature or provisioning profile and is not directly installable. No Swift/Objective-C implementation or new dependency is introduced.

The bundle records its actual checkout SHA, dirty state, version/code and RELEASE/unsigned variant. Dirty-source permission is local-only; CI requires clean same-source metadata. The Kotlin verifier checks the real ZIP central/local directory agreement, safe paths, Unix file types/permissions, CRC/size bounds, Mach-O CPU/platform/minimum/entry point and absence of signatures. It verifies iPhone+iPad declarations, actual opaque icon PNGs and compiled catalog, all four same-source CMP string resources, complete file hashes and retained known license bytes. Package inspection explicitly leaves signed-device execution, minimum-system runtime, full P0 and complete SBOM acceptance unverified.

PR CI keeps the existing ARM64 macOS runner, Simulator startup and all original Native tests. The device IPA and its receipt travel inside the existing source-bound iOS artifact. The strict staged aggregator re-inspects the package and requires exactly seven candidates, retaining all original Android/Intel/Windows checks. It uses the producer digest for the final IPA copy; the existing candidates reuse each computed source digest instead of hashing it repeatedly. Four final package targets remain: macOS ARM64, both Linux AppImages and Windows x86_64. All eleven final assets and the original `releases.yml` prepare → matrix build → package → publish expansion remain M6 work; this preflight does not publish anything.

This is independent implementation using the existing EhViewer Kotlin/Native pipeline and public Gradle archive/Apple bundle conventions. No new Animeko code, assets, scripts or dependencies are reused. Targets are `app/ios/build.gradle.kts`, `DeviceInfo.plist`, the existing Apple metadata helper and Kotlin verification/CI wiring. The previously audited platform-ownership boundary remains unchanged; the Kotlin-only entry and Rust/static archive integration are retained.
