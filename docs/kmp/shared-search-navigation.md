# Shared search recovery and page ordering

The original-layout restoration supersedes the earlier fixed page/reload/sort controls described below: normal browsing now retains service order and uses actual scroll continuation and pull refresh. The Android navigation case exercises those gestures, both cursor error/retry paths, retained loaded galleries, committed query/filter parameters, exact request counts and stale-request cancellation. Pure ordering regressions remain; the invented sorting dialog is no longer exposed on the home screen. Historical captures and failed runs remain retained.

The old search retry invoked a new first-page search using the editable query. After a next/previous request failed, editing that field could therefore send the retry to a different query and lose the failed cursor. The common CMP screen now freezes query, filters, cursor and direction for every attempt. A successful descriptor belongs to the displayed page; a failed descriptor belongs to its retry. Paging and the new Reload page action use those committed inputs. Editing the field remains a draft until Search or Apply and search. Failed paging/reload keeps the preceding results and cover cache available. Replacement/cancellation retains the existing generation guard so an old completion cannot replace newer results. Requests remain explicit and bounded; no automatic retry loop was added.

Sort this page explicitly reorders only the loaded results: service order, title, highest rating or most pages. It uses the same common cards, stable gallery identities and page-owned image cache. It never invents server sort parameters, changes cursors, mutates the original list/models or fetches other pages. Missing/invalid metadata sorts after known values, and ties keep service order. Returning to service order restores the original page. Dialog selection and cancellation use common Material3 controls; the action rows wrap for narrow windows and larger text. Android phones/tablets, Desktop and iOS compile the same implementation.

The repository also validates both decoded cursors before exposing navigation. ASCII numeric cursors with one optional numeric suffix are bounded to64 characters; malformed/oversized service metadata is a sanitized, recoverable invalid-response failure. Invalid input is rejected before a request. Real gallery tokens, existing Rust parsing/CBOR, Ktor transport/cookies and Android's original engine remain authoritative. No database, Native ABI, dependency or build-system change is needed.
