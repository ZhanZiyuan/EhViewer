# Shared download storage settings

Desktop and iOS now use one common CMP settings section to show committed download image bytes and choose an optional image budget. Choices are unlimited,256MiB,1/5/10/20GiB; a previously saved supported custom value remains visible. The default retains existing behavior. Raising or resetting the limit permits a failed download to be retried. Lowering it never deletes images, tasks or metadata, and previously saved pages remain readable. This is a committed-image budget, not a filesystem free-space guarantee: temporary files, current partial images and imported books are explicitly excluded in the UI.

The real `RoomGalleryDownloadStorage` checks the current preference inside its existing writer transaction before creating the next image or page row. All galleries share the same SQL aggregate; two storage instances cannot independently spend the same database budget. Invalid negative/oversized database lengths fail closed rather than cancelling out valid usage. Existing duplicate page commits keep their original integrity checks. Rejected admission leaves completed partial checkpoints available for retry. The underlying write/atomic-move/Room order, image hashes, cancellation and original queue failure/retry behavior remain intact; no downloaded content is automatically removed.

`DataStoreStoragePreferences` keeps a separate nonsecret schema1 record. Corrupt, invalid or future records are rejected on read/update/reset, without clearing their bytes. The same application-owned storage instance supplies the download queue and settings UI on each new platform. Android keeps its original download manager, paths and SAF implementation; the shared settings page links to the actual existing Android download-storage screen. It does not apply a second incompatible quota to that manager.

Reference decision: Animeko `docs/contributing/architecture.md:112–153` informed the common UI/domain/data/platform boundary.
