# Shared homepage entry

The normal Android shared destination and Desktop/iOS product entry now load the first gallery page automatically, following this repository's v1.15.10 `HomePageScreen(ListUrlBuilder())` and immediately collected `GalleryListViewModel` Pager. The existing common Compose list, Ktor session, Rust decoder and request-generation guard are reused. Embedded explicit-search callers retain their opt-in contract.

Returning from Downloads, Settings or the local library retains the loaded page without another request. An incoming local document stays offline until Galleries is selected. Failure waits for an explicit retry. Saved composition state restores the last submitted query/filter/cursor/tag/uploader route independently of unfinished search text. Identity changes clear the preceding account's route before returning to browsing.

Five actual Desktop Compose/Ktor regressions cover automatic entry, navigation, resize, composition restoration, draft isolation, explicit retry, cancelled-entry recovery after account navigation, offline local entry and embedded opt-in behavior. The Android navigation regression exercises the new initial request through the installed Ktor/Rust boundary while retaining all eight preceding pagination/retry/cancellation assertions. Exact iOS query input through the UI tool remains unverified. Phone and tablet each pass all 53 tests without skips on the identical final APK pair; raw Downloads empty/paused frames were reviewed.

No Animeko implementation, asset, dependency or script is copied. No new geometry or Golden tolerance is introduced by this entry change.
