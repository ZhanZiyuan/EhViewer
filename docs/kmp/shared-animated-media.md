The same CMP paged and continuous readers now retain encoded GIF/WebP data and animate only visible, resumed pages. This applies to service images, explicit originals, downloaded files and imported archive pages through their existing content providers. Static images and thumbnail sprites retain their previous decoder. Network transport, Rust ABI, databases, signing and stable application versions are unchanged.

Common Kotlin scans bounded GIF/WebP containers before animation allocation, rejects malformed/truncated chunks, limits input to 32 MiB and 1,000 frames, and accounts for compressed copies, poster, native canvas/disposal buffers and render handoff within the existing 64 MiB reader working-set estimate. Static images retain their 16-megapixel limit. This is allocation accounting, not a measured whole-process RSS ceiling. Large-image tiling, measured memory-pressure behavior and lowest-OS acceptance remain later verification.

Desktop and iOS compile the same Skia implementation. A worker owns one codec and mutable bitmap; immutable snapshots cross to one main-thread painter. Replacement, decode failure, cancellation, backgrounding and page removal close the actual Skia owners. Independent frame reconstruction delegates partial-frame composition and disposal to the installed codec. Finite playback retains its last frame until disposal. Common scheduling honors frame delays and additional repetitions and clamps sub-20-ms delays to 100 ms without busy spinning.

Android reuses the application's existing Coil 3.5.0 image loader, GIF decoder and Rust WebP decoder. ByteBuffer requests contain already-downloaded bytes and disable image caches. A request-scoped lease adopts a native drawable before publication, also closes late results after cancellation, and disposes it when the page stops playing. The existing WebP drawable now supports idempotent close, waits for its decoder worker and rejects drawing/restarting after disposal. A malformed later frame becomes one recoverable UI error; closed leases suppress late error delivery. Cancellation remains cancellation, and native faults/abort are not claimed to be catchable. Legacy reader disposal remains supported. No third-party implementation is copied or dependency version upgraded.
