# EhViewer application identity on each platform

The existing GPL-3.0-or-later EhViewer Android foreground vector remains the single mark source, including its four colors and stroke order. Android's adaptive, monochrome and density resources remain intact. No Animeko icon, resource, script or implementation is used. Generated resources are covered by EhViewer's existing packaged license; no new library or toolchain version is introduced.

A bounded Kotlin/JDK renderer reads this vector, normalizes the mark independently of Android's adaptive safe area and rejects unsupported path commands and external XML documents. Desktop uses a transparent padded tile; iOS uses an opaque 1024-pixel square and lets the operating system apply its mask. PNG payloads are encoded into real multi-resolution ICO/ICNS containers. The Gradle convention generates these resources from the repository source on each runner, without a local reference checkout.

| Platform | Integration | Validation boundary |
|---|---|---|
| Android | Existing adaptive/monochrome/density resources | Original four APK and phone/tablet acceptance retained |
| macOS | ICNS in the native application bundle; same PNG in CMP windows | Actual packaged Info.plist/ICNS bytes and seven native `iconutil` decoded renditions |
| Windows | Seven-size ICO for native packaging; same PNG in CMP windows | Actual Windows launch/package acceptance remains required |
| Linux | PNG for native packaging; same PNG in CMP windows | Actual Linux launch/package acceptance remains required |
| iOS/iPadOS | Real `actool` asset catalog for both SDKs; generated primary-icon metadata merged into the app | Actual device/simulator asset output and both iPhone/iPad bundle declarations; actual normal iPad home icon and restored CBZ page-2 pixels observed; eight original library files preserved |

Native distribution integration follows the [CMP packaging API](https://kotlinlang.org/docs/multiplatform/compose-native-distribution.html). Apple compilation follows the supported [single high-resolution asset catalog](https://developer.apple.com/documentation/xcode/configuring-your-app-icon); Simulator and device asset compilation are separate. Simulator signing is ad hoc; device compilation remains unsigned and does not establish signed-device or directly installable IPA acceptance.
