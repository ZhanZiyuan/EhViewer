# ADR 0018: Reject job declarations that the phase contract cannot classify

After accepted 76a8's complete ten-job Push/PR workflows and actual artifacts were closed in the ledger and same Draft PR, a boundary review found a latent enumeration gap. The phase scanner recognized only lowercase unquoted job headers without comments. An additional valid `future-target` or uppercase/quoted/commented header could be silently omitted, leaving the expected existing job set unchanged. This did not remove a job from the actual 76a8 workflow or change its real successful CI results, but it failed the contract's promise to reject undeclared jobs.

[GitHub job-ID rules](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-jobs) permit letters, digits, hyphens and underscores after the initial letter/underscore. Five actual temporary YAML fixtures, including hyphenated, uppercase, single/double quoted and commented extra-job headers, passed the installed actionlint. New regression tests on the old implementation then failed as expected: seven targeted tests, two failures, seven seconds. The undeclared hyphenated job was accepted; an unchanged reviewed job mapping with header comments was incorrectly rejected. Keep these failure receipts.

The repaired Kotlin scanner locates exactly one root jobs mapping, considers every nonblank/noncomment declaration at the reviewed two-space job indentation, and supports the complete unquoted ASCII identifier alphabet plus comments. It rejects unsupported headers explicitly, including quoted/anchored/flow forms, instead of ignoring them. Supporting another representation requires a separately reviewed parser change. It preserves job identity and detects duplicates; the original exact mandatory-job/dependency sets, always-run gate, state rejection, architecture checks and M2 metadata freeze remain unchanged. Gate-body extraction uses its actual validated header, so comments cannot hide or displace it. This is a bounded parser for the repository's reviewed layout, not a general YAML implementation; actionlint remains separately required.

Only this gate boundary and its regressions change. No product/platform target, workflow step, runner, timeout, dependency, Native implementation, reference reuse, version or production release behavior changes. Run all verifier tests and the original Android regression/preflights, then commit/push once and require the new exact SHA's complete Push/PR workflows and every actual artifact. No skipped or synthetic platform evidence is accepted.

The design comes from the actual EhViewer failure and GitHub's primary documentation. No additional Animeko code/design/resource/script/dependency or license reuse occurs. Preserve the accepted 76a8/eab4 evidence, original 23df/other historical failures and main's actually enforced trusted gate.
