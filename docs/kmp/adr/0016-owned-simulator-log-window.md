Status: isolated failure repair / LOCAL_VERIFIED / CI_PENDING. Version 1.15.10 / Android 180074 is unchanged. M2 and remote main protection remain incomplete.

PR job 123156698196 at 23df6bffe failed when the original `simctl log show --last 1h` command exceeded its original 30-second deadline. The failure-path capture subsequently retained 532,014 bytes with both actual process traces, but that cannot turn the first failed command into success. A similar failure was recorded at a7185893d; intervening successes did not establish a deeper fix. The rule declaration is not applied while this gate fails.

[Apple TN3163](https://developer.apple.com/documentation/technotes/tn3163-understanding-the-synchronization-of-nspersistentcloudkitcontainer) documents explicit start/end time frames with timezone offsets and a predicate; [WWDC22](https://developer.apple.com/videos/play/wwdc2022/10119/) shows the same CLI options. The installed Apple `log help show` also confirms `--start`, `--end` and `Y-M-D H:m:s+zzzz`. This verifies the supported query interface, not the service timeout's deeper cause.

Replace the preceding-hour query with the complete owned app test interval. Record UTC bounds just before the first cold launch and after the second process's required markers are observed; round outward with one additional second at each boundary. Preserve the entire original process/bundle predicate, output style/default levels and 30-second command timeout. This removes unrelated pre-launch boot history while retaining every tested lifecycle event. Early failure diagnostics start before boot; they do not weaken the primary failure result. Retain query-bound metadata alongside successful and failed captures.

Strengthen acceptance by parsing the actual unified log for each distinct positive Simulator-reported PID. Require both cold starts, Compose readiness, each Rust ownership probe, first background/foreground and second active state; require Rust result counts to agree with independently retained stderr. Missing events, wrong/reused processes, leaked ownership or truncated captures fail before startup.json is written. Preserve all existing screenshot, PID liveness, strict termination, cold-start, Rust/error/free and Simulator cleanup checks and deadlines. No retry, optional log, limit increase, skipped test or synthetic startup is introduced.

`ios-log-evidence` only parses a supplied trace for diagnostics; it does not boot an app or generate a successful startup receipt. Use it to check actual previously retained artifacts, including failed captures, without mislabeling those old runs. Unit tests cover UTC/offset/day/fractional boundaries, reversed ranges, every missing required event and wrong/reused PIDs/leaks. The new actual iOS jobs on both exact-SHA events and every original platform gate/artifact remain required before acceptance. Local iOS 27 boot was previously unavailable; do not claim a local new startup or a signed device/iPad result from parser tests.

The implementation is independent Kotlin in IosStartup.kt and its existing verifier/test entry points. There is no new Animeko adoption/code/script/resource/dependency, product/Native source, stable version, runner, production workflow or rule-fragment change.
