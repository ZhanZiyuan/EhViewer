# ADR 0020: Produce an actual source-bound Windows ARM64 staging ZIP

Status: IMPLEMENTED / LOCAL_VERIFIED / CI_PENDING. M2 remains incomplete; 1.15.10 / Android 180074 is unchanged.

Both complete eleven-job workflows and all actual artifacts of b6e4d passed before this slice began. M2's remaining packaging aggregation needs actual installation containers as inputs. The current Windows ARM64 technical spike only retained an application directory in an Actions artifact; that transport ZIP did not establish the release container, complete payload inventory or embedded source metadata.

Add an independent Kotlin staging packager and mandatory producer step using the existing Windows ARM64 image and same-source measured runtime/JVM proof. Preserve all Core, FFI, Unicode, manifest, ownership and two-window requirements. Recheck every native image header and measured hash, then inventory all image files, produce the correctly named real ZIP and read back every byte/CRC/path/source receipt. Keep the original directory/runtime evidence and add a separate package artifact. Existing strict gate dependence on the Windows job makes this step mandatory without introducing a skipped or optional category.

The first scope is Windows byte-container correctness. Full ZIP-extracted launch acceptance, actual staged cross-platform aggregation and the other final formats remain explicit outstanding work. No placeholder runtime, renamed extension, production secret, formal Release/tag, source target/dependency upgrade or version change is introduced. The original source-bound runtime report is required; tests of container mutation alone cannot stand in for native execution.

Reference paths are EhViewer's own WindowsNative.kt, DesktopWindows.kt, ReleaseContract.kt, existing source/provenance checks and the user's PRD. All new maintained implementation is Kotlin using existing JDK/Groovy JSON APIs. No additional Animeko architecture or AGPL implementation/resource/script/dependency reuse occurs. Whole verifier, original Android tests/lint/build/preflights, real local CLI input and both exact new-SHA hosted workflows with actual ZIP downloads remain mandatory.

Local proof uses the actual previously accepted clean b6e4d Windows ARM64 image/report, while explicitly recording the uncommitted packager state. All 176 files, 35 real ARM64 PE images, notice hashes and 128,705,101 expanded ZIP bytes passed the real CLI, external unzip and independent extracted byte/CPU audit. Final ZIP SHA is dada6d2c4cfef2f85ed038e2da9f99a86130cf08c1bdf5dcf709644338e1815f. Six real CLI proof mutations, dirty CI and overwrite attempts failed as required. No new local Windows execution is claimed.

First formatting failure (4s) and test-first source-receipt case collision (one failure/6s) and output-parent link overlap (one failure/7s) are retained. Both defects were fixed without relaxing checks: Windows receipt collisions are rejected and canonical existing output parents are checked before atomic creation. The complete final verifier suite passed 168 tests with zero failures/errors/skips in 47s; original Android319 tasks/tests/lint/build passed in1m37s,44 executed/275 reused. All original preflights, shared-core bytes, source/phase/architecture/contract CLIs, actionlint and whitespace passed. New-SHA Windows native execution and all other applicable hosted gates/artifacts remain mandatory before acceptance.
