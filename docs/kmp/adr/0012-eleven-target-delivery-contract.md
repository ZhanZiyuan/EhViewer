# ADR 0012: A delivery plan cannot certify installation packages

Status: M2 first slice, local validation passed; exact new-SHA CI still required. M1 passed both complete gates and all actual artifacts on `2f00e595ca74cd89b1d8d860077884b8306fdf54`. Version remains 1.15.10 / Android 180074.

The original release workflow safely handles four Android APKs. Adding seven filenames to that workflow without real package builders and validators would misrepresent delivery. Establish the eleven-target contract independently first, then build its actual package validation and aggregation in M6.

The Kotlin `ReleaseContract.kt` owns target identifiers, exact names, required runner/CPU, format, signing and Rosetta requirements. The CLI reads one authoritative source version/code and current full Git SHA; CI refuses dirty sources. Optional tag requests must match that source version, so planning v1.16.0 against current v1.15.10 fails without modifying any application metadata. Output explicitly states CONTRACT_ONLY, artifacts_verified=false and publish_enabled=false. A planned tag is not created.

The version-code range retains compatibility with the [official Android versioning guidance](https://developer.android.com/studio/publish/versioning): positive values no greater than the Google Play limit of 2,100,000,000. This range check does not establish that a code is unused or monotonically newer; the remote/history conflict audit and independent M8 version commit remain required.

The separate name-set validator rejects missing, duplicate, extra, nested, mixed-version and incorrectly spelled assets. It cannot establish format, actual CPU, runtime, executable entry, signatures, source or checksum correctness. Those checks remain mandatory, with their own real evidence, before M6/M8 acceptance. The final aggregator must call the name contract in addition to validating actual package contents, not use it as a replacement.

The existing mandatory Android CI job runs this local, secret-free command after the original source checks and retains its JSON in the existing verification artifact. No new network/credential capability is introduced. Production releases.yml, prepare/build/package/publish, original Android signing/diagnostics and offline publication regression remain intact. Subsequent M2 slices still need phase/source/license checks and staged dry-run evidence; this small slice does not claim M2 completion.

Read-only reference review: Animeko docs/contributing/testing.md, .github/workflows/build.yml target/test organization and .github/workflows/README.md. Adopt the concept of explicit target/test responsibilities; reject generated workflow scripts, retry/cancellation behavior, bot instructions, production account flows and release policy reuse. The eleven names/runners come from the user's contract, not Animeko. Target files are this Kotlin contract/test, Main.kt, ci.yml and release-artifacts.md. No AGPL implementation/resource/script/dependency tree is copied or mechanically rewritten; implementation remains independent project Kotlin with no new dependencies. The reference snapshot still has no verifiable Git metadata. Exact fingerprints and test results are recorded in reference audit and ledger.

Validation covers the exact eleven names and every runner/CPU choice, Rosetta only for Intel production on ARM, all four original Android ABIs, unsigned IPA boundary, every missing target/duplicate, extra/nested/wrong-case names, version mismatch/early 1.16 request, invalid/ambiguous source metadata and nonzero full SHA. A valid name fixture explicitly retains artifacts_verified=false. Full original verifier and Android regressions remain required before commit, followed by both exact-SHA CI events and actual artifacts.

Final local evidence: all 133 verifier tests passed with no failures/errors/skips (40s), including CRLF/tab metadata. The complete 319-task Android regression passed (1m44s), followed by every original Native/diagnostic/Java17/signature/JNI/ABI/16-KiB/four-APK snapshot preflight. The real CLI produced the current source-bound plan and refused an early v1.16.0 request and dirty CI source. Source policy, workflow lint and whitespace checks passed. This is local evidence only; per-SHA CI and actual artifact results belong in the ledger after the independent push.
