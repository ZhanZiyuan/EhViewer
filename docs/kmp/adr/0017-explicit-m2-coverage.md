# ADR 0017: Make unfinished M2 coverage explicit without relaxing checks

Status: IMPLEMENTED / LOCAL_VERIFIED / CI_PENDING. All 153 verifier tests passed with zero failures/errors/skips after correcting the identifier parser's rejection of the real digit-bearing desktop_linux_arm64 job. The original complete Android regression passed (319 tasks, 44 executed, 275 reused, 1m55s), with all original Native/diagnostic/Java17/signature/JNI/ABI/64-bit16-KiB/four-APK snapshot preflights, real phase/source/architecture/contract CLIs and actionlint/whitespace checks. Both complete exact-SHA workflows and all actual artifacts remain mandatory. M2 remains incomplete. Stable version 1.15.10 / Android 180074 is unchanged.

The current aggregate gate validates the actual Android, iOS, host Rust/JNI, Intel DMG producer/consumer, Linux ARM64 runtime, Windows ARM64 and source-policy jobs. This proves the completed slices, but does not describe which final deliverables or check categories are still missing. An aggregate success must not be presented as full five-platform product or eleven-package acceptance.

Add a Kotlin phase contract for the reviewed M2 job set, explicit aggregate dependencies, original Android-only core architecture and frozen M2 metadata. Require each final target to have a declared current CI surface, clearly distinguishing host-only proof, runtime/image spikes, APK preflights and unintegrated application delivery. Retain `milestone_complete=false` and declaration-only scope, with dedicated shared-KMP and actual staged packaging aggregation listed as pending. Run the CLI within the existing mandatory source-policy job and retain a separate source-bound phase JSON artifact; no optional result, skipped platform, fake build or synthetic package becomes a success.

Negative regressions remove every mandatory dependency, alter/duplicate/add jobs, conditionalize the gate, corrupt the source SHA and prematurely change/duplicate version authority. Existing result-state and publication regressions remain intact. Run the full verifier suite, original Android tests/lint/build, all Native/signature/APK preflights and actionlint; commit/push once and require both complete exact-SHA workflows and actual artifacts before continuing. No new platform implementation is introduced here.

The user's PRD M2 requirement and actual EhViewer modules/workflow are the design inputs. No additional Animeko code/design, resources, scripts, dependency or license reuse occurs. The original Android-only guard is deliberately retained until a separately tested M3 source-set migration; it must not simply be removed to obtain a green phase result. Main trusted-gate protection deployed after accepted eab4 remains in force, and original 23df/other CI failures remain historical failures.
