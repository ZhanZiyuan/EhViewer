# Shared floating search bar and list margins

The shared search page now follows Android 1.15.10's `SearchBarScreen` and `GalleryList` layout on every platform. The header row, outlined field and Search button are replaced by a Material 3 `SearchBar`: a 56dp pill, centered, at most 720dp wide, with 16dp side margins. Its placeholder shows "EhViewer" until focused, then the search hint, as Android's title/hint swap does. Leading is the drawer button on phones, as on Android's list (system Back still leaves an embedded screen); beside the rail it is Back when the platform embeds the screen, otherwise a search icon. Trailing actions are icon buttons: clear (while focused with text), Search and Filters. Filters is tinted primary and announced as "Filters applied" while filters are active, replacing the separate text. Sort this page moves into the page row with Previous, Reload page and Next, because it only applies to a loaded page.

Results scroll beneath the bar. The grid uses Android's `gallery_list_margin_h` (12dp, 20dp from `sw600dp`, 76dp from `sw720dp-land`, chosen from the window size), 4dp vertical margin and 12dp spacing, with top padding of the bar height plus 16dp. A nested-scroll connection slides the bar away with the content and back, as Android's `searchBarOffsetY` does; a new result or a page sort brings it back. The 1040dp content cap and 16dp page padding no longer apply to search; other destinations keep them.

Targets: GallerySearchBar.kt (new), GallerySearchScreen.kt, GalleryListStyle.kt, GalleryIcons.kt (Close), the four catalogs (`gallery_clear_search`), GalleryListStyleTest.kt and the new headless GallerySearchBarTest.kt. That test renders the real bar at 411/600/752/1280px and checks its width and centering against Android's rule. Android UI tests find the field by its label (content description), submit with the Search button through `submitSharedSearch()` and open filters by their description. No assertion, deadline or business step was removed.

Local results: Android spotless/unit/host/lint/assemble, shared Desktop78 and the iOS arm64/simulator compile and debug link passed; source policy passed. The first phone run failed 3/50: Back replaced the drawer button in Android's embedding, so the language and shared-gallery tests could not open navigation. That was fixed by preferring the drawer button. The second phone run failed 1/50 in the download pause test (partial page 0 of 35 bytes, a write/pause race). It then passed alone 3/3, in its class, after the language test, and in a third full phone run of 50/50. The tablet passed 50/50 serially with the same APK pair and zero skips. Phone screenshots show Menu, the EhViewer placeholder and the trailing actions; tablet screenshots show the rail, the centered 720dp bar, Filters tinted while active and 76dp landscape margins. No Desktop window or iPad interaction has been recorded for this change yet.

Remaining parity gaps: Android's expanded search view with suggestions and inline advanced filters, the FAB page actions, centered loading/error tips, the downloaded/read-progress card details and long-press actions.

Animeko was not consulted for this change; no AGPL code, assets or scripts are used. M5/M7/M8 stay open; stable 1.15.10/180074 and Draft PR15 remain.
