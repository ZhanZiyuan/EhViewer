# Shared adaptive navigation

The shared library screen replaces its rows of text destinations with one common CMP navigation shell, following Android's original drawer order and Material window-size classes. Windows narrower than 600dp (phones) show a compact header with Back, a menu button and the title, and open a modal drawer with icon/label items and a selected indicator. Back closes an open drawer first. Windows 600dp or wider (tablets, Desktop, iPad) show an 80dp navigation rail beside the content. Readers register as immersive and hide the rail, like Android's full-window reader. The destinations are Galleries, History, Downloads, Local library (when the platform provides archives), Account and Settings. Choosing a destination returns to its root and keeps the existing exit side effects: leaving Settings reloads appearance/language/list preferences, and opening Account cancels pending search. Android still opens its original account screen.

The search field gains a leading search icon, and Filters/Sort become Material filter/assist chips with icons. "Filters applied" stays visible as text. Icons are local Apache-2.0 Material path data, so the shared module does not take on the large icon artifact on Desktop/iOS. The content stays in one composition slot at every width, so resizing between drawer and rail keeps search and screen state. New strings are added to all four catalogs.

Targets: GalleryNavigation.kt, GallerySearchScreen.kt, GalleryReaderScreen.kt, the four catalogs and GalleryNavigationShellTest.kt. The new headless Desktop test renders the real shell at 411/600/800/1280px and checks the drawer opener, rail width, reader immersion, and that content survives a 1280→411→1280 resize without recreation. Android UI tests now reach shared destinations through SharedNavigation.kt. On phone widths it opens the drawer, using the localized label in the language test; on tablets it taps the rail. No assertion, deadline or business step was removed.

Local results: Android spotless/unit22/host58/lint/assemble and shared Desktop70 plus the new4 passed. iOS arm64/simulator compilation and the iOS debug link passed. The production phone run passed 50/50 and the serial tablet run passed 50/50, both with the same APK pair and zero skips. Phone screenshots show the header and drawer; Back closed the drawer and left the user on search. Tablet screenshots show the rail. No Desktop window or iPad interaction has been recorded for this change yet.

Animeko was not consulted for this change; no AGPL code, assets or scripts are used. M5/M7/M8 stay open; stable 1.15.10/180074 and Draft PR15 remain.
