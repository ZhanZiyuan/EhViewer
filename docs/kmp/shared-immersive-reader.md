# Shared immersive reader

This M5 UI slice gives online, downloaded and archive reading the same full-window canvas and overlay controls. It retains the existing bounded image/page window, actual Rust decoding, cancellation and decoded-only progress persistence.

The reference is EhViewer `v1.15.10`, commit `423b8af13632896b55780783b54b5f720ec4c9dd`: `app/src/main/kotlin/com/hippo/ehviewer/ui/reader/ReaderScreen.kt` and `eu/kanade/tachiyomi/ui/reader/{ReaderAppBars,ChapterNavigator,PageIndicatorText}.kt`. The new common `GalleryReaderChrome.kt` follows the original default black canvas, initially hidden controls, small page indicator, two-line Material top bar and 200ms sliding bars. It removes the library's 1040dp cap/keyline while reading, without changing the composition slot or losing the surrounding page state.

Supported actions remain real: all six original reading modes, bounded zoom/reset and display/original image selection. The seek slider resolves real page tokens; it never saves a requested position before the image decodes. Continuous seeking uses the existing page window and keyboard-dismiss restoration. Center taps and Space toggle controls; edge taps use the current validated previous/next links. Existing keyboard paging remains, and continuous reading gains viewport-sized Up/Down/PageUp/PageDown scrolling. The page indicator supplies a localized accessibility action to reveal the controls.

The six-mode menu follows the same tag's `ReadingModeType.kt`, `BottomReaderBar.kt`, `GalleryPager.kt`, `PagerViewer.kt` and `WebtoonViewer.kt`: Default resolves to Webtoon for an actual webtoon tag and otherwise RTL; Vertical uses the original snapping pager on the vertical axis; Webtoon has no page gap and Continuous vertical has a 15dp gap. The common menu reuses EhViewer's own original vectors, four localized catalogs, anchored Material menu and medium wide button geometry. Android retains native codes 0–5 and preserves unknown codes on unrelated edits. Older common snapshots keep their actual layout/direction without a write; explicit new selections round-trip without replacing decoded progress. Mode switches retain the actual decoded page and existing overlay. No Animeko code, dependency or platform ABI is added. Orientation/crop controls, complete reader settings, full-page visual parity and performance acceptance remain open.
