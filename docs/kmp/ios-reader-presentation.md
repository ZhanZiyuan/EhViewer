# iOS immersive reader presentation

This M5 slice brings iOS system-bar behavior into the same CMP reader state as the original Android default fullscreen mode: hide the status bar with hidden reading controls, show it with the controls, and restore ordinary presentation when leaving the reader. Online, downloaded and archive reading share that state. This is an incremental UI change; complete pixel equivalence and M5/M7/M8 acceptance remain open.

The visual/behavioral reference is EhViewer `v1.15.10`, commit `423b8af13632896b55780783b54b5f720ec4c9dd`, `app/src/main/kotlin/com/hippo/ehviewer/ui/reader/ReaderScreen.kt`, particularly the default fullscreen preference and `appbarVisible` system-bar synchronization. Targets are common `GalleryNavigation.kt` / `GalleryReaderScreen.kt`, iOS `GalleryUIViewController.kt`, the Kotlin application entry and the existing Desktop shell scene tests. No Animeko implementation, resources, scripts or dependency set were copied.

The common reader provides a window-scoped native presentation lease. Disposal restores the previous host; resizing keeps the surrounding reader/navigation state. UIKit uses a parent controller containing the existing Compose controller. Four viewport constraints allow real resizing/rotation, while shared screens continue to apply their own safe drawing insets. Status-bar visibility uses supported controller preferences and `setNeedsStatusBarAppearanceUpdate`, following [Apple's controller contract](https://developer.apple.com/documentation/uikit/uiviewcontroller/childforstatusbarhidden). The exact installed Compose 1.12.0 metadata marks the old controller delegate deprecated, so it is not used. The ordinary Kotlin lease owner remains separate from Objective-C inheritance, and its callback holds the parent weakly to avoid a content/controller retain cycle.
