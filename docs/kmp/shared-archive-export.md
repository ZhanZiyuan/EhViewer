# Shared archive and image-folder export

The common CMP local library adds an Export action. Desktop uses a real save dialog and iOS uses UIKit's [document export/copy picker](https://developer.apple.com/documentation/uikit/uidocumentpickerviewcontroller/init%28forexporting%3Aascopy%3A%29). Android retains its existing export routes; the new shared data contract is also tested with actual packaged Android JNI. No new dependency, Rust ABI or persisted book schema is introduced.

`ArchiveLibrary.prepareExport` creates a bounded private snapshot before handing it to platform UI. Compressed archives retain every original byte, including encryption, without requesting a password or extracting pages. Recognized outer signatures determine an appropriate suffix; unknown/SFX containers keep a generic archive suffix. Image folders export only validated pages, in their existing natural order, as `000001.ext`, `000002.ext`, and so on. Source filenames, unrelated sidecars and private metadata are not exported. Suggested names use an opaque book identity and can be changed in the platform save UI.

The caller owns the snapshot through completion or cancellation and closes it in `finally`. It remains independent of book deletion and library shutdown. `close` is idempotent, drains an admitted save through its mutex and finishes private cleanup despite caller cancellation; a cleanup failure remains an explicit error. The platform receives an immutable copy rather than the live private book.

Desktop saving creates a new file or folder exclusively, rejects private-library destinations and never merges or replaces existing user data. File lengths, SHA-256 and source metadata are checked while streaming in 64 KiB chunks. An interrupted external copy is retained because it may contain user changes; the UI reports the uncertainty and offers another export under a new name. This is recoverable copying, not a claim of atomic publication at the external destination. Private staging is removed after completion/cancellation; automatic crash-orphan collection remains separate work.

## Reference decision

Read-only Animeko `app/shared/app-platform/src/commonMain/kotlin/platform/features/PlatformComponentAccessors.kt` informs only the platform-capability boundary. Targets are `ArchiveExport`/`FileArchiveExport`, `ArchiveLibraryScreen`, `DesktopArchiveExport` and `AppleArchivePicker`. Adopt explicit adapters, adapt them to EhViewer's actual archive/image ownership and reject nullable no-op capabilities, service lookup, unrelated features and reference implementations. No AGPL source, resource, script or dependency is copied or mechanically rewritten. The original supplied snapshot still has no verifiable Git SHA; it is never built or modified.

## Verification and limits

Twelve real-file cases cover preserved archives, ordered folders, independent ownership, existing destinations, corruption, preparation and external-copy cancellation, retained partial copies, write failure and cleanup retry. A first write-failure injection missed the canonical destination on macOS; only the injector path was corrected, preserving its failure log and assertions. Actual runtime regressions separately export/reopen a real PNG ZIP, reimport an exported image directory and preserve/decrypt a real AES archive. These extend the original six packaged archive checks to nine.

Local Android/shared tests, Release lint, four APKs and benchmark assembly passed the full 542-task gate. Actual receipts passed JVM data63/network135/reader47 and 241 verifier tests. Both Kotlin-only iOS targets compiled; actual Native data57/network135/reader47, Keychain3 and two cold starts with archive9/account4 checks each passed, with 2,000 Rust results per launch and zero live results. The standalone Desktop build passed its actual JNI gallery5/account4/history3/archive9 checks, affected data/network tests and bundled-runtime application packaging.

Final phone and tablet each passed **46/46** unfiltered instrumentation tests on identical APKs: application `1b682ad954d5019231819aa8770744bcbc3c1b8b61497bf2c8cdc48ddd608af9`, test APK `6eb627996f94640faae167a35f219ab61291d5666c62cf0f5c5830e55c8b41e0`. Both task-owned emulators were shut down with data retained.

Normal iPad execution used the same tested executable, SHA-256 `44e6578e8b8fbd882e7e3e4af871cd453ed515a154c9501678a7091da197beef`. The real system picker saved a CBZ and an ordered two-image folder, returning `Export saved.` in the common UI. The system CBZ matched its private source exactly; both exported PNGs matched their corresponding private pages. A third picker was cancelled, returning `Export cancelled.` without adding output. All eight original library files, provider source fixtures and previous output hashes remained unchanged; no `.export-*` directory remained. Temporary keyboard capture was restored off and the owned iPad was shut down with its data retained. Evidence is under ignored `build/kmp-work-logs/archive-export-*`, including device receipts, Native startup, iPad round-trip hashes and cancellation capture. Normal Desktop save-dialog interaction, general sharing and this feature commit's hosted checks remain unverified/pending.

Snapshots can duplicate up to the existing 8 GiB book limit; low-space/provider errors are explicit. Large-book throughput, RSS, provider latency and minimum systems remain unverified. File export does not establish general share-sheet integration or complete F06/M5 acceptance. Version remains 1.15.10 / Android 180074 and PR #15 remains Draft.
